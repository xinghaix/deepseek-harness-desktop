# Session deletion research (primary sources)

Scope: inspected the five requested installed DSH bundles and repository `internal/dsh/desktopbridge`; no web sources used.

## JSONL persistence

- **Artifact path.** The configured root is resolved at construction, and `locate(meta)` returns `{ kind: "jsonl", path: logPath(root, meta.cwd, meta.id, compression) }`. `logPath` uses the current session-format generation. The path is `<root>/<projectDir(cwd)>/<encoded-session-id>/<generation-log-filename>`; undefined `cwd` uses `<root>/_no-cwd`. The session id is escaped as one safe path segment; the physical suffix is `.jsonl` or `.jsonl.zstd`. [dsh-session-persistence-jsonl/lib/index.js:L742-L762](/opt/homebrew/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-session-persistence-jsonl/lib/index.js#L742-L762) [dsh-session-persistence-jsonl/lib/index.js:L895-L938](/opt/homebrew/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-session-persistence-jsonl/lib/index.js#L895-L938) [dsh-session-persistence-jsonl/lib/index.js:L2283-L2312](/opt/homebrew/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-session-persistence-jsonl/lib/index.js#L2283-L2312)
- **`listArtifacts(signal)`.** Ensures root encoding, scans project directories then session directories, selects one generation per directory, reads its header, skips unsupported generations, throws on duplicate session ids, and returns entries shaped as `{ header, path: selected.sourcePath }`. [dsh-session-persistence-jsonl/lib/index.js:L2859-L2888](/opt/homebrew/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-session-persistence-jsonl/lib/index.js#L2859-L2888)
- **`list(options)`.** Returns materialized artifact snapshots plus this process's created-but-unmaterialized sessions; order is explicitly unspecified. [dsh-session-persistence-jsonl/lib/index.js:L2450-L2481](/opt/homebrew/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-session-persistence-jsonl/lib/index.js#L2450-L2481)
- **`resolveCurrentLog(id, signal)`.** Returns `undefined` when no generation exists or only a historical generation exists; returns `selected.sourcePath` only for the current format; a future format throws `SessionFormatUnsupportedError`. [dsh-session-persistence-jsonl/lib/index.js:L2700-L2716](/opt/homebrew/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-session-persistence-jsonl/lib/index.js#L2700-L2716)
- **Deletion boundary.** No public session-delete method was found in this installed backend. Its close/release bookkeeping removes the handle from `openHandles`, drops a writer claim, and removes `pending` only when the session never materialized; it does not delete a materialized artifact. [dsh-session-persistence-jsonl/lib/index.js:L355-L377](/opt/homebrew/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-session-persistence-jsonl/lib/index.js#L355-L377) The write lock is `session.lock`; releasing a lease closes the descriptor but intentionally never removes that lock file. [dsh-session-persistence-jsonl/lib/index.js:L614-L643](/opt/homebrew/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-session-persistence-jsonl/lib/index.js#L614-L643) A delete flow therefore needs active-agent/handle coordination before removing on-disk session data.

## Workspace registry

- **Detach is an entity method, not a registry method.** `WorkspaceEntity.detachSession(sessionId)` rewrites only the record's ordered `sessionIds` array, filtering out the id. The entity getter also filters membership by the host's canonical session path. There is no `WorkspaceRegistry.detachSession` method in the requested source. [dsh-workspace/lib/index.js:L90-L153](/opt/homebrew/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-workspace/lib/index.js#L90-L153)
- **Archive.** `workspaceRegistry.archiveSession(id)` is durable and idempotent; it validates that the session is known (live, indexed, or in persistence), then appends the id to the registry-global `archivedSessionIds` set. Workspace accounting is not changed. [dsh-workspace/lib/index.js:L431-L456](/opt/homebrew/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-workspace/lib/index.js#L431-L456)
- **Unarchive.** `unarchiveSession(id)` removes the id from the global archive list and does not re-check session existence; an archive entry for a gone session still resolves, and a non-archived id is a no-op. [dsh-workspace/lib/index.js:L457-L476](/opt/homebrew/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-workspace/lib/index.js#L457-L476)
- **Do not confuse workspace deletion with session deletion.** `workspaceRegistry.delete(workspaceId)` explicitly retains the workspace directory and every session log; it only removes the registration/table record. [dsh-workspace/lib/index.js:L391-L400](/opt/homebrew/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-workspace/lib/index.js#L391-L400)

## Agent scope disposal

- A `ReactLoopAgent` creates an agent scope with `createScope(loopCtx, this)` and exposes `scope.ctx` as its context. [dsh-agent-loop/lib/index.js:L727-L760](/opt/homebrew/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L727-L760)
- The lifecycle disposer is memoized and registered before publication. It aborts setup, waits for in-flight publication/driver construction, calls `machine.cancel({ kind: "disposed" })`, waits for `machine.whenIdle()`, awaits `machine.scope.dispose()`, closes the persistence handle, detaches agent and session registrations, then untracks the disposer. [dsh-agent-loop/lib/index.js:L1619-L1679](/opt/homebrew/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L1619-L1679)
- The owner effect yields `machine.scope.rawDispose`; owner teardown aborts setup and calls the same disposer. Factory teardown also stops accepting work and awaits every live-agent disposer and startup task. [dsh-agent-loop/lib/index.js:L1680-L1691](/opt/homebrew/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L1680-L1691) [dsh-agent-loop/lib/index.js:L1387-L1392](/opt/homebrew/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L1387-L1392)

## Archived-session settings page (desktop-bridge)

As of DSH `0.1.7-rc.1`, `@deepseek-ai/dsh-client-ui-settings-unarchive-sessions` is no longer shipped in `dsh-web-app` (last published npm: `0.1.6-alpha.2`). Desktop-bridge owns the page instead:

- Registers `settings.section` id `archived-sessions` (order 25, locale `settings.archivedSessions`, zh nav 「已归档会话」) via the same `ctx.slots.inject("settings.section", …)` API still used by official settings packages on 0.1.7.
- Reads `useWorkspaces` → `items` + `archivedSessionIds` and `useSessions` → `byId` (GlobalStandardProps). Newest archive first; ids without a loaded summary produce no row.
- First-class UI: search, empty / unavailable / emptySearch states, per-row Unarchive, plus desktop batch select / select-all / batch unarchive / batch delete / per-row delete (`data-dsh-archived-batch*`, `data-dsh-delete-archived-session`). MutationObserver decoration still enhances a foreign Unarchive list if one appears, but skips `[data-dsh-archived-sessions-page]`.
- Writes: `ctx.uiWorkspace.unarchiveSession` and desktop RPC `deleteSession` (same host path as the session-menu delete).
- Reference unpack of the dropped package (do not npm-install into global dsh): `@deepseek-ai/dsh-client-ui-settings-unarchive-sessions@0.1.6-alpha.2`.

## Attachments / ownership

- The JSONL header schema contains only session metadata (id, cwd, parent/origin, agent preset, etc.); no attachment field or separate attachment artifact is defined in the requested persistence source. [dsh-session-persistence-jsonl/lib/index.js:L777-L840](/opt/homebrew/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-session-persistence-jsonl/lib/index.js#L777-L840)
- The desktop bridge treats attachments as rendered message-DOM content: it recognizes DSH media/file wrappers and metadata attributes, then extracts media `src`/`alt` or file `name` plus optional `data-file-path` into overlay parts. [internal/dsh/desktopbridge/lib/client.js:L823-L868](../../internal/dsh/desktopbridge/lib/client.js#L823-L868) [internal/dsh/desktopbridge/lib/client.js:L1249-L1299](../../internal/dsh/desktopbridge/lib/client.js#L1249-L1299)
- Historical content is obtained through the session binding for the active session and `session.loadThrough(seq)`; the bridge then mirrors the loaded prompt DOM. It has no attachment persistence or file-delete operation. [internal/dsh/desktopbridge/lib/client.js:L1744-L1767](../../internal/dsh/desktopbridge/lib/client.js#L1744-L1767) [internal/dsh/desktopbridge/lib/client.js:L1859-L1892](../../internal/dsh/desktopbridge/lib/client.js#L1859-L1892)
- **Conclusion:** these allowed sources do not establish that attachment files are session-owned. Treat attachments as message/session content references rendered by DSH, not as files the desktop session-delete flow may safely unlink; external-file ownership needs a separate authoritative source.
